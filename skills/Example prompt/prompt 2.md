# THE LIVING ARCHIVE

Build an extraordinary interactive website for a fictional institution called **THE LIVING ARCHIVE**.

It is a private digital archive dedicated to preserving humanity's most important creative artifacts — photography, film, music, architecture, typography, objects, manuscripts, and experimental digital works.

But the website itself is the archive.

The user should feel as though they have entered a gigantic, intelligent, living collection rather than a normal website.

This should be an ambitious, award-level creative web experience.

Do NOT make it look like a generic museum website.

Do NOT make it look like a generic AI website.

Do NOT use purple gradients, glassmorphism, floating cards, generic dashboards, excessive glowing UI, or template-like sections.

The experience should feel:

**editorial + architectural + cinematic + intelligent + tactile + mysterious.**

---

# CORE CONCEPT

The archive contains millions of objects.

But instead of presenting them as a grid, the website represents the archive as a **living spatial system**.

Everything exists somewhere within the archive.

The user's journey through the website should feel like moving through an enormous building whose architecture is continuously changing.

The fundamental metaphor is:

> **The archive remembers everything.**

---

# 1. OPENING — THE DOOR

The website initially displays almost nothing.

A massive word sits in the center:

**ARCHIVE**

The letters are enormous and almost touch the edges of the viewport.

Below it:

**01,847,293 OBJECTS**

The number should subtly change as though the archive is continuously indexing itself.

The cursor should initially appear as a tiny dot.

When the cursor moves:

The typography should subtly react to its position.

Move toward the center:

The letters compress.

Move toward the edges:

The letters expand.

Move rapidly:

The typography should exhibit slight inertia.

After several seconds, a tiny message appears:

**ENTER THE ARCHIVE**

The entire word should then split apart.

The user enters through the typography.

Do not use a conventional page transition.

---

# 2. THE ARCHIVE SPACE

The user enters a huge visual environment.

At first it appears almost empty.

There are enormous walls, columns, frames, shelves, and floating objects.

The environment should feel architectural.

However, the architecture should not behave like a normal 3D scene.

It should continuously transform.

As the user scrolls:

- walls move;
- corridors extend;
- ceilings disappear;
- objects emerge;
- typography appears on surfaces;
- rooms transform into other rooms.

The user should feel like scrolling is controlling a camera travelling through an impossible building.

---

# 3. THE CAMERA

The camera is one of the main characters.

Scrolling should control its journey.

The camera should:

- move forward;
- occasionally rotate;
- pass through architectural structures;
- move vertically;
- transition between rooms;
- occasionally move sideways;
- slow down naturally.

Do not make the camera move linearly.

Introduce subtle easing and changes in velocity.

At certain moments, the camera should appear to pause while the environment continues moving around it.

The result should feel cinematic rather than like a Three.js demo.

---

# 4. THE ROOMS

The archive consists of different rooms.

Create at least six.

### ROOM 01 — IMAGE

Photography.

Large photographs should exist as enormous physical surfaces.

Some should hang from walls.

Some should float.

Some should appear as transparent planes.

Hovering an image should cause it to subtly react.

Clicking it should bring the image toward the user.

The image becomes the entire viewport.

---

### ROOM 02 — SOUND

This room represents music.

Instead of normal album cards, represent musical works as physical forms.

Use abstract geometry.

Different sounds should correspond to different visual characteristics.

For example:

- bass → scale;
- volume → brightness;
- frequency → movement;
- rhythm → pulsing.

If sound is enabled, the environment should respond subtly to the audio.

Sound must be OFF by default.

---

### ROOM 03 — TYPOGRAPHY

Create an enormous typographic room.

Words should exist as architectural structures.

For example:

**FORM**

**LANGUAGE**

**MEMORY**

**TIME**

Some words should be horizontal.

Some vertical.

Some should be partially hidden behind walls.

Some should exist in the distance.

Scrolling through this room should cause typography to move at different depths.

Create convincing depth through parallax.

---

### ROOM 04 — OBJECTS

Create a room containing strange physical objects.

Examples:

- a chair;
- a camera;
- a sculpture;
- a cassette;
- a CRT monitor;
- a book;
- a piece of industrial equipment.

Do not use random decorative 3D objects.

Each object should feel like an archived artifact.

Hovering an object should reveal:

**OBJECT 008391**

**1974**

**UNKNOWN MAKER**

Moving the cursor around it should affect lighting and perspective.

---

### ROOM 05 — FILM

This room should feel dramatically different.

Create a massive cinema-like environment.

A gigantic screen appears in the distance.

A short abstract film or animated texture plays.

As the camera approaches, the screen becomes increasingly distorted.

Eventually the screen fills the entire viewport.

The transition should feel like entering the film.

---

### ROOM 06 — DIGITAL MEMORY

This is the strangest room.

Instead of physical objects, the environment contains fragments of digital artifacts.

Floating windows.

Broken typography.

Old interfaces.

Pixel fragments.

Glitching imagery.

Fragments of HTML-like structures.

Do not turn this into a generic cyberpunk scene.

It should feel like digital archaeology.

---

# 5. THE ARCHIVE INDEX

At any point, the user should be able to summon the archive index.

Use a minimal gesture or button.

The entire environment should freeze.

The screen becomes extremely editorial.

Display:

**THE ARCHIVE**

Then categories:

**IMAGE**

**SOUND**

**FILM**

**OBJECT**

**TYPE**

**SPACE**

**DIGITAL**

The categories should not appear as cards.

Use enormous typography.

Hovering a category should cause the rest of the typography to react.

Selecting one should cause the world to reorganize around that category.

---

# 6. SEARCH

Create a search experience.

But do NOT create a standard search input.

When the user activates search:

The entire screen should become a giant text field.

The cursor becomes a vertical line.

The user types directly into enormous typography.

Example:

**SEARCH: ARCHITECTURE**

As they type:

The archive begins reacting.

Objects appear.

Images emerge.

Words move.

The environment changes.

Search results should feel like the archive is responding to the query.

---

# 7. MEMORY EFFECT

Create one signature interaction called:

**MEMORY**

Whenever the user spends time looking at an artifact, that artifact should subtly remain present after leaving it.

For example:

The user views a photograph.

They leave the room.

Later, a faint fragment of that photograph appears somewhere in the environment.

Not prominently.

Almost subconsciously.

Over time, the environment accumulates visual memories of the user's journey.

The website should therefore feel like it remembers the user.

---

# 8. PARTICLE SYSTEM

Create a particle system representing archived data.

At certain points, thousands of tiny particles should appear.

They should form:

- letters;
- images;
- architectural shapes;
- abstract objects.

The particles should respond to:

- cursor position;
- cursor velocity;
- scroll;
- proximity to objects.

The particles should be capable of dispersing and reconstructing.

Use GPU acceleration where appropriate.

---

# 9. DESTRUCTION / RECONSTRUCTION

At one point, deliberately destroy the environment.

The archive should begin to fall apart.

Walls fragment.

Typography breaks apart.

Images dissolve.

Particles scatter.

The camera continues moving.

Then everything slowly reconstructs.

The sequence should communicate:

**“Even when the archive breaks, the memory remains.”**

This should be one of the major cinematic moments of the website.

---

# 10. TYPOGRAPHIC PHYSICS

Typography should behave as though it has physical properties.

Different text elements can:

- stretch;
- compress;
- rotate;
- collide;
- drift;
- fragment;
- attract;
- repel;
- distort.

The user should feel that the letters are objects rather than flat HTML.

Do not make every text element behave this way.

Reserve the strongest effects for important moments.

---

# 11. MICRO INTERACTIONS

Introduce subtle interactions throughout the experience.

Examples:

Hovering an image:

**VIEW**

Hovering an object:

**EXAMINE**

Hovering a room:

**ENTER**

Hovering an unknown artifact:

**UNKNOWN**

Some interactions should deliberately feel mysterious.

Not every element needs to explain itself.

---

# 12. THE ARCHIVE NUMBER

Keep a tiny counter visible somewhere:

**OBJECTS REMEMBERED: 000000**

As the user interacts with artifacts, this number increases.

For example:

**OBJECTS REMEMBERED: 000014**

This should represent the user's personal journey.

At the end, show:

**YOU REMEMBERED 27 OBJECTS.**

---

# 13. FINAL EXPERIENCE

After the user has travelled through enough of the archive, the environment gradually empties.

The architecture disappears.

The artifacts disappear.

The typography disappears.

Eventually there is only a blank space.

Then:

**WHAT DO YOU REMEMBER?**

appears.

The user's previously viewed artifacts should briefly appear as fragments around the sentence.

Then everything disappears.

Final text:

**THE ARCHIVE REMEMBERS FOR YOU.**

Below:

**ENTER AGAIN**

The experience loops back to the beginning.

---

# 14. CURSOR

Create an advanced custom cursor.

The cursor should have contextual states:

DEFAULT

VIEW

ENTER

EXAMINE

SEARCH

DRAG

The cursor should respond to velocity.

Fast movement should stretch it.

Slow movement should compress it.

Certain objects should magnetically attract the cursor.

Some should repel it.

The cursor should never feel like a decorative circle pasted over the website.

---

# 15. SCROLL

Scrolling should feel physical.

Use smooth scrolling.

The environment should react to scroll velocity.

Fast scrolling:

More motion blur / stronger environmental movement.

Slow scrolling:

More precision.

Stopping:

The environment should settle naturally.

Do not trigger every effect with arbitrary scroll thresholds.

Whenever possible, make the experience continuous.

---

# 16. RESPONSIVE DESIGN

Mobile should NOT be a shrunken desktop.

Design a dedicated mobile composition.

Replace hover interactions with touch interactions.

Use gestures where appropriate.

Reduce expensive 3D effects when necessary.

Preserve the central concept of travelling through the archive.

Typography must remain dramatic.

---

# 17. ACCESSIBILITY

Despite the experimental presentation:

- use semantic HTML;
- maintain keyboard navigation;
- provide focus states;
- support reduced motion;
- ensure important information exists outside WebGL;
- provide accessible names for interactive elements;
- provide alternative navigation for users who cannot use the primary visual experience.

The archive must remain usable.

---

# 18. PERFORMANCE

This experience should be ambitious without being stupid.

Implement:

- lazy loading;
- optimized textures;
- compressed 3D assets;
- adaptive rendering quality;
- device capability detection;
- efficient animation loops;
- WebGL resource cleanup;
- reduced effects on weaker devices;
- responsive image loading;
- reduced-motion mode.

Use pre-rendered or baked assets when they produce a better performance/quality tradeoff.

Do not render thousands of expensive objects simply because the GPU can theoretically handle them.

---

# 19. TECHNOLOGY

Choose the architecture intelligently.

Possible technologies include:

- Next.js
- React
- TypeScript
- GSAP
- ScrollTrigger
- Lenis
- Three.js
- React Three Fiber
- WebGL
- GLSL
- Canvas
- Rive
- Web Audio
- Blender-generated GLB/GLTF assets

Do not use every technology just to demonstrate technical complexity.

Choose the simplest technology capable of producing each effect.

Use shaders where shaders make sense.

Use CSS where CSS is sufficient.

Use Canvas where a particle system is more appropriate.

Use Three.js for the spatial environment.

Use pre-baked assets when appropriate.

---

# 20. ART DIRECTION

The visual language should combine:

- museum architecture;
- Swiss/editorial typography;
- brutalist scale;
- contemporary digital art;
- cinematic photography;
- archival materials;
- subtle imperfection.

The color palette should be restrained.

Primarily use:

- black;
- white;
- warm paper tones;
- muted grey;
- occasional single accent colors.

Avoid rainbow gradients.

Avoid generic futuristic neon.

Avoid “AI aesthetic.”

---

# 21. SOUND

Sound should be optional.

When enabled, it should make the environment feel alive.

Potential sounds:

- distant room ambience;
- subtle mechanical sounds;
- projector noise;
- paper movement;
- low-frequency environmental tones;
- subtle interaction sounds.

The soundscape should change between rooms.

Do not turn the website into a video game.

---

# 22. TECHNICAL ARCHITECTURE

The system should conceptually behave like:

USER INPUT

↓

Pointer / Touch / Scroll / Keyboard

↓

Interaction State

↓

Animation / Physics / Camera State

↓

DOM + Canvas + Three.js + Shader Systems

↓

Rendered Experience

The architecture should avoid dozens of disconnected animation systems.

Prefer coordinated state and shared animation timing.

---

# 23. THE FINAL TEST

When the website is finished, ask:

**Does this feel like a website?**

If the answer is yes, redesign it.

It should feel like:

**walking through an impossible museum built by someone who understands cinema, typography, architecture and software.**

The user should be curious about what happens next.

---

# SUCCESS CRITERIA

The experience succeeds if:

1. The opening immediately establishes a unique identity.
2. The user feels like they are entering somewhere rather than loading a website.
3. The 3D environment feels architectural rather than like a collection of floating models.
4. Typography feels physically integrated into the environment.
5. Scroll controls a continuous journey.
6. The archive contains multiple distinct environments.
7. Cursor interaction feels physical.
8. Particles are used meaningfully rather than decoratively.
9. The environment remembers previously viewed artifacts.
10. Search feels integrated into the world.
11. At least one major destruction/reconstruction sequence exists.
12. The site has a memorable signature interaction.
13. Mobile is intentionally designed.
14. Accessibility remains functional.
15. Performance is treated as a first-class requirement.
16. The visual language remains coherent throughout.
17. The experience does not rely on generic “AI website” aesthetics.
18. The final result feels like an actual piece of digital art.

Most importantly:

**The user should leave the website remembering the experience, not merely remembering that it had animations.**
